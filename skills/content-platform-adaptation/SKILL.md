# 多平台内容适配

## 何时用

手上已有一篇定稿（中文或英文），要分发到公众号 / 知乎 / 领英 / X 等平台。
**注意：这不是「复制粘贴」任务，是「重写」任务。**

## 铁律一：各平台发不同版本

不要逐字复制全文到多个平台。两个理由：

1. **判重**：同一篇全文同时出现在高权重平台（如知乎）和自有站点时，搜索引擎倾向把高权重平台当正本、自有站点当副本 —— 等于自己压自己。
2. **阅读场景不同**：各平台的入口机制（搜索 / 推荐 / 订阅）、读者预期、完读行为都不一样。

（例外：公众号内容不被公开搜索引擎索引，与自有站点不构成判重。）

## 铁律二：逐平台检查「自证句」

凡是**指涉「本文自身」的句子**，换平台后必须重新验证是否还成立。

已踩过的实例：

> 公众号版编后记：「仅『发布』一步为人工操作 —— **你正在读的这一篇**，就是文中流程的直接产物。」

这句话搬到知乎**不成立**：知乎版是手工同步的，没走公众号 API 上传。照搬即不实陈述。

正确改法：把指涉对象从「你正在读的这一篇」改为「本文的公众号版本」—— 证据闭环保留，假话去掉。

**检查清单（逐条核）：**

- [ ] 编后记 / 结尾里的「本文」「这一篇」「你正在读的」，指的是哪个平台的版本？
- [ ] 文中提到的产物（文件、链接、后台、草稿箱、截图）在该平台上是否真实存在？
- [ ] 引用的数字 / 统计是否出自当前这篇文章的发布路径？
- [ ] 品牌名与产品能力描述在该语言语境下是否仍然准确？

## 各平台适配动作

### 公众号（中文）

- 平台内无外链、无横向滚动、无代码高亮 → **代码块转图**，宽表转图或改列表式
- 排版靠 `<table>` + `<td>` 内联样式（思路等同 HTML 邮件）
- 字段上限（实测，非文档口径）：`title` 加权 **128**、`digest` 加权 **240**；加权 = 中文计 2 / ASCII 计 1
- 推送流程与全部踩坑见 skill `wechat-mp-draft`

### 博客站（中英双语，SEO/GEO 主资产）

- 保留完整长文 + 附录 + 结构化问答（FAQ）
- 这是**正本**。其他平台的版本应比它更短、或做实质差异化

### 知乎（中文）

- 流量以**搜索**为主 → 标题取搜索导向，直接命中检索词；疑问式标题有效
- 支持 Markdown → **代码块原样保留**，不必像公众号那样转图
- 表格可用，但注意移动端宽度
- 读者看完会想自己试 → 末尾加「想自己复现？最短路径」清单（前提 + 步骤）
- 完读率低于博客站 → 可考虑改发精简版（结论 + 核心干货 + 复现清单）

### 领英 / X（英文）

- 面向欧美 MarTech 读者：**中国特有平台须降级为「案例」**（一段说明 + 一句背景），不要当教程主体
- 主线升维为通用命题（例：当 API 文档与运行时行为不一致，Agent 该怎么工作）
- 领英版基于**英文版成稿**做本地化改写，不是逐句翻译
- 英文版成稿本身是博客站资产（面向 SEO），**不要按领英语境写**，否则博客站版失真

## 交付形式

- `{slug}.{platform}.md` —— 带元数据的完整版
- `{slug}.{platform}.paste.md` —— 去掉 frontmatter 的纯正文，便于直接粘贴发布
